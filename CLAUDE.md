# Parameteo

Application web d'aide à la décision pour le **parapente** : émagramme AROME interactif, plafonds thermiques, sites de vol FFVL notés et balises de vent. Public : pilotes de vol libre francophones. **Toute l'interface et les messages sont en français.**

Site publié : https://raphaelvdv.github.io/Parameteo/ (GitHub Pages, branche `main`, dossier racine). Pousser sur `main` met le site en ligne en 1 à 2 minutes. Il n'y a ni build ni dépendance npm : on édite les fichiers tels quels.

## Fichiers

| Fichier | Rôle |
|---|---|
| `index.html` | Toute l'application : HTML, CSS et JavaScript dans un seul fichier (~1 900 lignes) |
| `logo.svg` | Logo « Aube » (voile fuchsia, relief bleu à courbes de niveau, cumulus, ascendance, isothermes à 45°) |
| `icon-192.png`, `icon-512.png`, `apple-touch-icon.png` | Icônes générées à partir de `logo.svg` (à régénérer si le logo change) |
| `manifest.webmanifest` | Installation sur l'écran d'accueil (nom, couleurs, icônes) |
| `.nojekyll` | Sert les fichiers tels quels sur Pages |

Le logo est aussi **inclus en ligne** dans l'en-tête de `index.html` (`<div class="brand">`), avec des identifiants préfixés `lg-` : le mettre à jour aux deux endroits.

## Organisation du script (`index.html`)

Sections repérées par des commentaires `// ---------- … ----------`, dans cet ordre :

1. **Constantes et thermodynamique** : `es`, `mixr`, `theta`, `moistStep` (pseudo-adiabatique en RK4), `lclOf` (NCA de Bolton), `thetaW`, `thetaE`.
2. **Exemple fictif** (`EXAMPLE`) : profil affiché au démarrage et dans le didacticiel, toujours signalé comme fictif.
3. **Préparation du sondage** (`prepare`) et interpolation en ln p (`interpS`, `envT`, `envTd`, `envZ`, `windAtZ`, `pAtZ`).
4. **Analyse** (`analyze`) : particule (surface, couche mélangée, plus instable), CAPE/CIN en température virtuelle, NCA/NCL/NE, indices (LI, K, TT), eau précipitable, isotherme 0 °C, cisaillement 0–6 km, **plafond sol et plafond relief** (`thermalFrom`) avec diagnostic « couche brassée » / « couvercle sous les crêtes ».
5. **Rendu** (`draw`) : émagramme 761 sur canvas, isothermes inclinées à 45°, couleurs lues dans les variables CSS.
6. **Panneaux**, **Import Open-Meteo / texte** (`loadOpenMeteo`, `sndFromHour`, `parseText`), **Événements**. La tuile « Source du sondage » est **masquée** (`section.source[hidden]`) : ses champs (`lat`, `lon`, `model`, import) restent utilisés en interne. Le choix du lieu se fait dans la barre `.topbar`, à droite des onglets, visible dans les deux onglets (`#locForm` : recherche de commune via le géocodage Open-Meteo, liste `#preset` affichée s'il y a plusieurs résultats, bouton « Ma position ») ; choisir un lieu charge le sondage **et** lance la recherche des sites. Le sondage (`tryFetch`) attend 30 s ; les erreurs d'Open-Meteo sont traduites par `omReason` (quota par minute, heure ou jour de l'offre gratuite) et affichées dans la tuile Situation et sous le titre de l'émagramme (`situMsg` → `#situMsg`, `#sndMsg`) ; quota par minute = nouvel essai automatique après 61 s (2 fois au plus).
7. **Didacticiel** (`TUT`) et **Lecture commentée** (`READ`) : même moteur d'étapes (`renderStep`, `curSteps`), textes de la lecture générés à partir des données.
8. **Sites de vol** : terrains FFVL (`ffvlTerrains`, `ffvlSitesAround`), OpenStreetMap / ParaglidingEarth en option (`getExtraSites`), prévision par paquets (`fetchForecasts`), analyse par site (`analyzeSpot`), **ensoleillement des pentes** (`sunPos`, `slopeSun`), **cohérence du secteur** (`loadSector`, `sectorEval`, `windAtAltD`), **notation** (`RULES`, `scoreSpot`), carte Leaflet et classement en volet (`renderSpots`, `setSide`), **clic n'importe où sur la carte** (`clickPoint`, `pointHtml` ; `loadSpot("point")` charge son sondage). **Regroupement** (`clusterMarkers`, `cluFiche`, réglages `CLU`) : jusqu'au zoom 12, les marqueurs (option `info` : déco, balise, webcam, atterrissage) à moins de 46 px se fondent en une bulle (meilleur déco du groupe, nombre d'éléments, 📷 s'il y a une webcam) à partir de 3 éléments (2 sous le zoom 10) ; le marqueur choisi n'est jamais regroupé ; bulle **composite inspirée de Spotair** (MarkerCluster, `iconCreateFunction`) : rose des orientations favorables des décos du groupe (`roseSvg`), notes du meilleur déco, **balise de synthèse** (`cluBeacon` : vent médian, direction moyenne si les balises concordent à 60 %, rafale max, couleur `beaconCls`), 📷 ; un clic affiche la liste du groupe dans le volet et, jusqu'à 15 éléments, **déploie le groupe sur place** (`spiderfy` : cercles concentriques de 6 puis ×1,4, cercle en tirets fuchsia, traits vers la vraie position ; `unspider` au clic sur la carte, au zoom et au rendu) ; bouton « Zoomer sur ce groupe ». Puis **écartement des marqueurs** (`declutter`, recalculé au zoom) : marqueurs avec l'option `dc` (priorité décos 3 > balises 2 > atterrissages 1), décalés en CSS sur leur élément enfant, trait fin vers la vraie position ; pas de transition CSS sur ces marqueurs (fausserait la mesure). Sous le zoom 12, les balises n'affichent que leur flèche (classe `zlow`). **Pas de bulle Leaflet** : un clic sur un marqueur (déco, atterrissage, balise, point cliqué) affiche sa fiche **dans le volet de droite** (`showFiche`, `hideFiche`, bouton « ← Classement ») pour que la carte ne bouge jamais ; le marqueur choisi est entouré (`.sel-mk`). Un clic sur une ligne du classement centre la carte et ouvre la fiche.
8 bis-0. **Vigilance Météo-France** (tuile `#vigi` en tête de l'onglet Situation, `VIG`, `vigDepartment`, `vigData`, `vigFor`, `renderVigi`) : API portail Météo-France `GET https://public-api.meteofrance.fr/public/DPVigilance/v1/cartevigilance/encours` avec l'en-tête `apikey` (CORS ouvert, vérifié). **Clé de l'utilisateur**, saisie dans Paramètres et gardée seulement en `localStorage` (`emagramme-mf-key`) — ne jamais mettre de clé dans le code. Format (doc. technique Météo-France sur data.gouv) : `product.periods[]` (`echeance` J / J1) → `timelaps.domain_ids[]` (`domain_id` = numéro de département) → `max_color_id`, `phenomenon_items[]` (`phenomenon_id` 1 vent … 9 vagues, `phenomenon_max_color_id`, `timelaps_items[]` avec `begin_time`, `end_time`, `color_id` 1 vert … 4 rouge). Département du lieu via `geo.api.gouv.fr/communes?lat&lon` (sans clé). Cache 15 min. **Diagnostic de clé** (`mfKeyInfo`, `mfWhy`) : la clé « API Key » du portail est un JWT dont on lit localement `exp` et `subscribedAPIs` (rien n'est envoyé) → message « clé expirée le … », « non abonnée à Bulletin Vigilance », codes de la passerelle WSO2 (900901 identifiants invalides, 900900 clé mal formée — HTTP 500, 900908 interdit, 900800 quota) ; avertissement si la clé expire dans moins de 7 jours. Bandeau `#vigiBanner` dans « Où voler » si orange ou rouge aujourd'hui (les notes n'en tiennent pas compte). Couleurs officielles `--vig1…4`. **Non testé sur une vraie réponse** (pas de clé dans l'environnement de développement).
8 bis. **Situation générale** (tuile `#situ`, `situSeries`, `situAnalyse`, `renderSituation`, `drawSituation`) : lecture synoptique locale de la prévision du lieu choisi (`S.dataset`), recalculée à chaque heure ou lieu. Type de temps (front froid : chute de T850 ≥ 4 °C en 12 h, ou ≥ 3 °C avec pluie ou rotation du vent à 700 hPa ; front chaud : hausse ≥ 3 °C avec baisse de pression, nuages moyens et hauts ou pluie ; puis dépressionnaire < 1008 hPa, anticyclonique ≥ 1020 hPa, tendances ±4 hPa / 12 h, marais barométrique, sinon « Flux … » d'après le vent à 700 hPa), résumé en clair, graphique 48 h (pression mer, T850, pluie, nuages bas/moyens/hauts, vent à 700 hPa, nuits, fronts repérés, heure choisie) et liens vers les cartes de fronts officielles (Met Office, DWD) — pas d'image intégrée (adresses non vérifiables). Variables ajoutées à la prévision : `pressure_msl`, `cloud_cover_mid`, `cloud_cover_high`.
8 bis-1. **Tendance 5 jours** (tuile `#trend` sous la situation, `TR`, `trUrl`, `loadTrend`, `trDays`, `renderTrend`, `drawTrend`, `trRead`) : requête séparée Open-Meteo `meteofrance_seamless` (AROME puis ARPEGE), `forecast_days=5`, gardée 1 h en mémoire par lieu. Cartes par jour (heures de vol 10–18 h : flux moyen à 700 hPa, T850, pluie 8–20 h, type de temps de `situAnalyse` à 14 h, repère Favorable / À surveiller / Défavorable selon `RULES.trend`, sans effet sur les notes) ; météogramme sur canvas : flux à 850/700/500 hPa, nuages H/M/B, pression mer, T850, T 2 m, pluie, nuits, heure du sondage ; survol ou toucher = valeurs horaires dans `#trRead`, clic sur un jour = surlignage et résumé. Sur téléphone, les jours passent en liste.
8 ter. **Onglets** (`TABS`, `switchTab`) : « Situation générale » (`#pane-situation` : tuile situation + carte des fronts) et « Où voler » (`#pane-voler` : carte des sites, émagramme, lexique, niveaux). Onglet mémorisé (`localStorage` `emagramme-tab`) et dans l'adresse (`#situation`, `#voler`). Les cartes Leaflet d'un onglet masqué sont redimensionnées et recadrées à l'affichage (`SP.visFit`). Les boutons Lecture commentée et Didacticiel basculent sur « Où voler ».
8 quater. **Carte des fronts** (`#fronts`, `FR`, `FRG`, `loadSynoptic`, `frFields`, `frAnalyse`, `renderFronts`, `frText`) : grille ARPEGE Europe 1,5° × 2° (36–60° N, 14° O–20° E, ~300 points, 3 requêtes de 100 points, gardée 3 h en `localStorage`), pas de 3 h sur 72 h. Isobares (marching squares sur champ lissé et suréchantillonné ×3, tous les 4 hPa), centres D/A (extrêmes locaux), **fronts automatiques** par paramètre de front thermique (TFP) sur θe à 850 hPa : ligne TFP = 0 au maximum du gradient (≥ 1,6 K / 100 km), type selon l'advection du vent à 850 hPa (froid > 0,6 K/3 h, chaud < −0,6, sinon quasi stationnaire). Les segments de front sont **assemblés en lignes** (extrémités communes), les lignes de moins de 250 km sont écartées, puis lissées (Chaikin, 2 passes) ; type = majorité des segments ; symboles tous les ~170 km. Texte : centres d'action, gradient de pression et vent géostrophique au lieu, front le plus proche, passage prévu dans les 24 h. Fond **Esri Canvas** gris clair / sombre (sans clé ; CARTO exige désormais une clé et affichait « API KEY REQUIRED »).
8 quinquies. **Webcams** : (1) liens « Webcam : https://… » extraits des textes FFVL (`camLinks` sur `description` / `tourist_info` des terrains et `remarques` des balises, champ `cams`), affichés dans les fiches (`camsHtml`) et par 📷 dans le classement — sans clé ; (2) option **Windy Webcams API v3** (`WC`, `loadWebcams`, `drawWebcams`, `camFiche`) : `GET https://api.windy.com/webcams/api/v3/webcams?nearby=lat,lon,km&limit=50&include=images,location,urls,player` avec l'en-tête `x-windy-api-key`, **clé de l'utilisateur** saisie dans Paramètres (`localStorage` `emagramme-windy-key`, jamais dans le code), case « Webcams » dans les options, marqueurs `.pin.cam` (priorité d'écartement 1), fiche : flux en direct en `iframe` seulement si `player.live` existe ; sinon **dernière image** (`images.current.preview`), relue toutes les `RULES.cams.refresh` min tant que la fiche est ouverte (`WC.timer`) ; l'accéléré 24 h (`player.day`) n'est qu'un lien (jugé peu pratique par l'utilisateur) ; images de l'offre gratuite valables ~10 min, donc relecture après 9 min. **Non testé sur une vraie réponse** (`api.windy.com` bloqué dans l'environnement de développement), attribution « Webcams fournies par windy.com » obligatoire.
9. **Balises** : FFVL et Pioupiou (`fetchFFVL`, `fetchPioupiou`, `beaconFor`), comparaison prévu / mesuré (`compareBeacon`, `cmpHtml`).
10. **Paramètres** (`rulesHtml`) : fenêtre en lecture seule générée depuis `RULES`.

## Règles métier à respecter

- **Les notes (décollage et thermique, sur 100) reposent uniquement sur la prévision.** Les balises ne servent qu'à la comparaison prévu / mesuré, active à moins de 2 h de l'heure choisie.
- **Tous les seuils de notation sont dans l'objet `RULES`.** Modifier un seuil = modifier `RULES` uniquement : `scoreSpot`, `compareBeacon` et la fenêtre « Paramètres » le lisent. Ne pas écrire de seuil en dur ailleurs. L'utilisateur ne peut pas modifier les règles depuis l'interface (choix voulu).
- Les textes affichés doivent rester prudents : la note est indicative et ne remplace pas les bulletins officiels, les balises ni la fiche du site.
- **Terrain IGN** (`loadTerrain`, `meanOri`, `terrHtml`, `slopeArrow`) : pour un **déco référencé**, l'orientation reste celle du déco et la pente est mesurée au MNT **sous le déco, dans son axe, sur 150 et 300 m** (la plus forte) — le point FFVL est souvent en retrait du bord (ex. Dent de Crolles : plateau vers le NO, falaise au S). Sans descente mesurée, pente supposée de 30°. Un déco aux orientations **non contiguës** (écart > 45°, ex. N et SE) est **découpé en un déco par face** (`oriGroups`, `splitFaces` ; id `…~k`, nom « · face … ») ; la prévision est demandée une seule fois par emplacement. Pour un **point cliqué**, pente et orientation locales (méthode de Horn, grille 3 × 3 à 25 m) ; si la pente ≥ 10°, elle sert d'orientation de « déco ». Flèche bleue = sens de descente.
- **Chauffe des pentes** (`slopeSun`, `heatWhy`) : chauffe du déco = **chauffe de référence** (réglage « Chauffe réf. », 4 °C : pente sèche face au soleil d'été, ciel clair, vent faible) × ensoleillement de la pente (incidence sur la pente IGN ou supposée) × **saison/heure** (rayonnement direct selon l'épaisseur d'atmosphère, formule de Meinel, ~100 % soleil haut, ~70 % midi d'hiver) × **saison** (`RULES.sun.season`, par mois : sol froid et humide, journées courtes ; 50 % en décembre-janvier, 60 % en novembre et février, 100 % de mai à août ; ajouté après un plafond surestimé au Margériaz le 3 novembre) × nuages (`cloud_cover`) × **vent au déco** (−50 % max. de 10 à 40 km/h) × **sol mouillé** (pluie des 24 h précédentes) × **neige** (`snow_depth`, si le modèle la fournit) × **nature du sol** (OpenStreetMap, `loadGround`, `classifyGround`, classes et facteurs dans `RULES.ground` : glacier 0,3, eau 0,45, roche 1,15, forêt 0,75, broussailles 0,9, prairie 1, cultures 0,95, bâti 1,05). Seuils dans `RULES.sun`. Les facteurs < 100 % sont affichés dans la fiche.
- **Cohérence du secteur** : pour les 10 meilleurs décos, 4 points voisins à 2,5 km (requête légère : vent, pluie, nuages bas) ; la variabilité rend la note plus prudente (retrait plafonné à 30 par note). Les autres décos affichent « non évaluée ».
- **Diagnostic nuages** (`cloudLayers`, `cloudState`, `cloudDiag`, `cloudHtml`, seuils dans `RULES.clouds`) : couches où T − Td ≤ 1,5 °C sur le sondage du déco, inversion au-dessus du sommet ; déco « dans », « au-dessus » (mer de nuages), « sous » la couche, « fragmenté » ou « dégagé » ; nature (stratus sous inversion, perturbation, étalement de cumulus) ; ouverture ou fermeture heure par heure jusqu'à 19 h selon le modèle ; dissipation par réchauffement (température au sol nécessaire pour que les thermiques traversent la couche et son inversion, comparée au maximum prévu), signalée comme douteuse si elle contredit le modèle. Au-dessus de la mer de nuages, les nuages bas sont ignorés pour l'ensoleillement et la note thermique, avec avertissement de sécurité (redescente impossible sans traverser la couche). Déco « dans » la couche sans saturation au point exact : −20 (`RULES.deco.cloud.edgePen`). Pastilles ☀ / ☁ sur les marqueurs et dans le classement.
- Un site FFVL **interdit** est noté 0 ; afficher statut, restrictions, avertissements et alertes FFVL dans les fiches.

## Sources de données (appelées directement depuis le navigateur)
**Quota Open-Meteo** (gratuit sans clé, par connexion Internet : ~600 appels/min, 5 000/h, 10 000/jour ; un appel par lieu, fractionné au-delà de 10 variables) : toutes les prévisions passent par le cache `omGetC` / `omPutC` (mémoire + IndexedDB `parameteo`/`om`, 1 h par point, purge à 12 h) ; les requêtes multipoints passent par `omPoints(pts, mk)` (points en cache réutilisés, les autres par paquets de 10). `omUse` estime la consommation du jour (`localStorage` `emagramme-om-use`), affichée dans Paramètres. Carte des fronts gardée 6 h. Ne pas ajouter de requête Open-Meteo hors de ce cache.


| Donnée | Adresse | Remarques |
|---|---|---|
| Prévisions | `api.open-meteo.com/v1/forecast` (modèles `meteofrance_arome_france`, `meteofrance_arpege_europe`, `meteofrance_seamless`), `/v1/elevation` | Niveaux de pression 1000 à 100 hPa, vent en nœuds (`wind_speed_unit=kn`) |
| Terrains FFVL | `https://www.data.gouv.fr/api/1/datasets/r/4375c95d-cf26-4e71-b72d-2e09be5a0e36` | `terrains.json`, ~3,7 Mo, mis à jour chaque jour ; gardé 24 h en `localStorage` |
| Balises FFVL | `…/datasets/r/8d795154-9145-4ab2-99de-6768a36f31ea` | `balises.json`, gardé 24 h |
| Relevés FFVL | `…/datasets/r/047b2ab9-627f-4e5f-9d68-5b948433c61d` | `releves.json`, toutes les 5 min ; vitesses en km/h |
| Terrain IGN (RGE ALTI) | `https://data.geopf.fr/altimetrie/1.0/calcul/alti/rest/elevation.json?lon=…|…&lat=…|…&resource=ign_rge_alti_wld&zonly=true` | Plusieurs points par requête (séparés par `|`), CORS ouvert ; valeurs < −1000 = hors couverture. Résultats gardés en `localStorage` |
| Nature du sol | Overpass (mêmes miroirs), requête `is_in(lat,lon)` + `make pt n=k` pour séparer les points ; point lu à 150 m sous le déco dans son axe | Non testé sur le vrai service (Overpass bloqué dans l'environnement de développement) ; résultats gardés en `localStorage` (`emagramme-sol`) |
| Balises Pioupiou | `https://api.pioupiou.fr/v1/live/all` | Les stations OpenWindMap ne sont pas dans les relevés FFVL |
| Sites (option) | Overpass (4 miroirs), ParaglidingEarth | Gardés 7 jours |
| Fonds de carte | OpenTopoMap, OpenStreetMap, Esri | Leaflet 1.9.4 via cdnjs |

L'API `data.ffvl.fr` exige une clé : **ne pas l'utiliser**, les mêmes données sont en open data sur data.gouv.fr (le lien `/api/1/datasets/r/<id>` redirige vers le fichier le plus récent et autorise les appels depuis le navigateur).

Pour tester depuis un environnement cloud, autoriser dans le réseau de l'environnement : `data.ffvl.fr`, `www.data.gouv.fr`, `static.data.gouv.fr`, `data.geopf.fr` (ce dernier est joignable : on peut tester avec les vraies altitudes IGN). Open-Meteo, Overpass et les tuiles n'étaient pas joignables depuis l'environnement de développement : les tester avec des réponses simulées (Playwright, `page.route`).

## Design

- **Thème « Aube »**, dérivé du logo : en-tête en dégradé abricot (`--band-top` → `--band`), commandes en bleu relief (`--accent`), **plafonds en fuchsia** (`--hi`), isothermes orangées (`--iso`). Mode sombre « crépuscule » via `prefers-color-scheme` et `[data-theme="dark"]`.
- Toutes les couleurs passent par les variables du bloc `:root` (et leurs deux redéfinitions sombres). Pas de couleur en dur dans les composants.
- Polices : **Archivo Narrow** (titres, étiquettes, boutons), **Archivo** (texte), **JetBrains Mono** (chiffres).
- Conventions de l'émagramme à conserver : courbe d'état rouge, point de rosée bleu, particule en tirets, notes vert ≥ 70 / orange 40–69 / rouge < 40.
- **Hiérarchie visuelle** (bloc « Passe de design » en fin de CSS) : tuiles sans bordure avec ombre douce (`--shadow`, `--radius` 10 px) ; boutons à trois niveaux — plein (action principale), `.soft` (teinté, secondaire), `.quiet` (discret) ; titre de section « Où voler ? », surtitre `.kick` pour l'émagramme ; barre de recherche `.searchbar`, réglages `.toolbar`, options secondaires et aide repliées dans `details.more` ; classement dense (`table-layout:fixed`, une ligne de raison tronquée `.why1`, pas de bouton par ligne : la fiche contient « Voir le sondage »).
- La page doit fonctionner sur téléphone (≈ 400 px, aucun défilement horizontal) et en plein soleil (contrastes suffisants).
